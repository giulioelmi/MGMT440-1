## Part 1 · What was finished

### Deep search (steps 20–22), `backend/agent/src/ask.ts`

| Piece | How it works |
|---|---|
| Plan | A forced `plan_research` tool call asks for exactly 4 sub-questions (contract limit 3–6), each with a short reason. The `plan` event is the **first** event on the stream, before any retrieval. |
| Planner model | **Haiku 4.5 by default** (`PLANNER_MODEL` in `.env.example`). Sonnet took ~4.1 s for the plan alone; the SLA is p95 ≤ 4 s. Sonnet still writes the answer. |
| Planner prompt | Split by the factors that decide the answer (never one sub-question per option), no overlaps, no textbook background, one real-world-practice question, no invented constraints, reasons say what each adds without guessing the answer. One worked example (deliberately not a benchmark question). |
| Hedge | The planner call is streamed only to see when it starts writing. Hedge at 1.5 s if it hasn't started (queued), and at 3.5 s if there's still no plan. First good plan wins; max 3 calls. Non-retryable errors (e.g. 400) fail at once with a 502. |
| Research | Up to 3 sub-questions in parallel. Each: its own `web_search` (+ `search_documents` with a Space), then up to 3 pages that no other sub-question has already taken. Every step and source carries `subQuestion`. Stays under the 24-call cap (2 held back). |
| Answer | One shared numbering. Sonnet (effort medium) writes: direct answer, one `##` section per sub-question, `## What is still unknown`. The synthesis may only `save_memory` (no retrieval, so attribution stays complete). |
| Spend gate | Atomic per-user, per-UTC-day counter in a `deepUsage` collection. Over `DEEP_DAILY_CAP` → `429 {error, status, resetsAt, requestId}`. A run that fails before streaming gives its slot back. |

## Part 2 · Phase 4 handoff: check it in the UI (steps 30–35)

### Setup (once)

1. `git checkout zahid/lumina && git pull`, then `npm install`.
2. **Your own `.env`** (copy `.env.example`): your own Anthropic, Tavily and OpenAI keys, and **your own
   free Atlas cluster** in `MONGODB_URI`. Leave `PLANNER_MODEL` empty (Haiku is the default).
3. `node scripts/create-indexes.mjs`, then `node scripts/create-indexes.mjs --status` until all three
   indexes say `queryable`.
4. **Free Atlas clusters pause when idle.** If anything returns `502 Topology is closed` or `/health`
   says `db: down`, resume the cluster in Atlas first.
5. Start everything: `npm run dev` → UI on http://localhost:5173, gateway on 8787, agent on 8000.
   To keep agent logs for later: run `npm run dev:agent 2>&1 | tee agent.log`, `npm run dev:gateway`
   and `npm run dev:web` in three terminals instead.
